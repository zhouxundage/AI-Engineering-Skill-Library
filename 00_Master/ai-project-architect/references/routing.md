# 专业工作路由

只在选择专业工作时读取本表；不一次性加载所有技能。先检查当前可用技能列表，按名称读取实际入口。技能不可用时执行等效步骤，说明缺失；本表不是可执行调度代码。

| 技能标识 | 使用条件/边界 | 核心交付 |
|---|---|---|
| architecture-design | 为新系统或跨模块改造定义边界、数据流、接口和架构决策。适用于横向基础能力与纵向业务切片设计；不用于单纯代码格式调整。 | 架构图/数据流、模块责任表、接口和错误契约、目录建议、关键 ADR、首个切片计划。 |
| software-engineering | 实现可重复运行的项目、业务模块和工程基础，处理环境、配置、契约、日志与注册机制。适用于脚本产品化或功能开发；不为简单编辑强加完整工程骨架。 | 实现代码、必要配置样例与依赖锁定、实际入口、操作说明、检查结果。 |
| testing-validation | 为软件功能设计并执行基于风险的单元、集成、端到端和业务验收，形成需求到证据的映射。模型回答质量使用 ai-evaluation。 | 按风险选择的测试计划、测试资产/记录、需求覆盖表、缺陷与验收报告。 |
| deployment-operation | 准备或执行已授权的软件部署、环境迁移和运行维护，设计发布、健康检查、监测和恢复。纯本地原型可只提供启动与故障处理说明。 | 环境配置、发布与回滚步骤、健康检查、运行手册、部署验证记录；实际发布仅在授权范围内执行。 |
| ai-system-design | 设计或改造 LLM 应用，判断规则、检索、模型调用或 Agent 的合理边界，并定义提示、结构化输出、数据与评估契约。 | AI 任务契约、非 AI 基线、候选方案比较、提示/输出规范、版本和降级策略、评估计划。 |
| rag-engineering | 构建或修复基于文档知识的检索增强流程，处理来源、解析、切分、权限、检索、引用和索引更新。用于知识问答或证据检索；一般文本生成无需启用。 | 摄取/检索规格或实现、元数据与索引版本、引用契约、检索与回答评估记录。 |
| agent-engineering | 设计或实现需要模型选择工具与多步执行的 Agent，定义工具契约、状态、预算、恢复和副作用控制。固定顺序流程优先普通工作流。 | 工具注册表与契约、状态转换、预算/重试/恢复策略、执行轨迹和行为验证记录。 |
| ai-evaluation | 建立和执行 LLM、RAG 或 Agent 的任务质量评估，管理黄金样例、指标、人工评分、回归与发布条件。用于回答或决策质量，区别于软件连通性测试。 | 评估集清单、指标与评分准则、运行记录、分层结果、失败案例和发布建议。 |
| product-strategy | 为新产品或方向调整澄清目标用户、问题、价值假设与成功指标。用于决定做什么和为什么做；已明确的小功能实现无需重新做策略。 | 产品简报、问题与价值假设、成功指标、优先场景、验证计划和停止/调整条件。 |
| mvp-design | 把已选产品场景裁剪成可验证价值的最小完整交付，定义范围、纵向切片、验收和迭代顺序。用于 MVP、试点或时间受限的首版。 | 范围与排除项、第一条可用路径、切片顺序、验收清单、试点学习计划。 |
| ux-ui-design | 设计工作流程、页面结构、交互状态和人工审核体验，或改进已有界面可用性。适用于面向用户的 UI；纯后台脚本不强制增加界面。 | 用户流程、页面/组件结构、状态矩阵、文案、线框或实现、可用性验证记录。 |
| clinical-trial-ai | 构建或审查临床试验文档与统计编程的 AI 工作流，如 SAP 到 Shell、TLF 规格或标准映射。强调来源、版本、盲态和人工核验；不用于诊疗决策。 | 来源清单、概念/字段映射、带原文定位的结构化草稿、问题清单、校验和人工审核记录。 |
| biostatistics | 把临床研究问题与 SAP 转成可复现统计规格、实现和核验，处理估计目标、分析集、模型、缺失数据与敏感性分析。用于研究分析，不替代临床诊疗。 | 分析规格、可复现脚本/环境（如要求实现）、诊断与核验记录、带限定条件的结果解释。 |
| pharma-regulatory | 在药企项目中把提供的 SOP、质量体系和适用法规映射为系统控制、验证证据与差距。用于明确合规范围或受控流程；不提供无依据的合规认证结论。 | 适用性清单、条款→控制→证据矩阵、差距与影响、验证建议、待确认责任事项。 |

## 责任分界

- Product Strategy 决定价值假设；MVP Design 裁剪首版；Architecture Design 负责模块/数据/接口边界。
- Software Engineering 实现环境与功能；Testing & Validation 检查软件行为；AI Evaluation 检查任务输出质量。
- AI System Design 选择 AI 机制；RAG 负责证据检索；Agent 负责工具执行与状态，只有任务需要时加入。
- Clinical Trial AI 负责文档语义与来源链；Biostatistics 负责分析方法规格；Pharma Regulatory 负责适用性与控制证据映射。
- UX/UI 与后端契约可迭代；Deployment 只进入当前授权的环境操作范围。

一次交接包含：任务目标、输入及版本、约束 ID、验收标准、产物及状态、真实验证证据、未决事项。已有产物满足要求则复用，不要求各技能重复出整套文档。

## 项目规模

轻量任务：目标、约束、执行、相关检查，可以一份简短记录完成。
普通项目：需求/架构/首个切片/验收，按需合并模板。
高后果或受控项目：根据实际适用要求增加追踪、独立核验和批准记录，不预设所有要求适用。
